> 2026-10-12 · **只做规划，未改任何代码**
> 参考对象：[Playa-Cyrene/Cyrene-Agent](https://github.com/Playa-Cyrene/Cyrene-Agent)（MIT，699★，同为 Electron + Live2D 的昔涟同人作品）
> 你已明确喜欢它的 **`pearl-white`（珍珠白）主题**，所以本规划以它为主线。

## 0. 目标与边界

**要做的四件事**（你提的）：

1. 界面**美化**，用「珍珠粉 + 白色」，更契合角色
2. 用户可**自定义桌宠大小**
3. 可**镜像翻转**
4. 可**开关某些功能**

**边界**（先定死，免得越做越大）：

- 我们**不是**它那样的 AI 伴侣（它有聊天/长期记忆/工具/语音/多渠道、213 个界面文件、8+ 个窗口）。
  我们的定位不变：**DSH 的状态显示器 + 派活入口**。UI 复杂度按它的 **1/10** 砍。
- 不改动：命中测试的既有语义、菜单定位逻辑（按身体居中）、`pet://` 协议与 CSP、素材版权红线。

### 0.1 ✅ 已确认的需求（2026-10-12，用户逐条回答）

| 项 | 确认结果 |
|---|---|
| 主题范围 | **只做亮色（珍珠白 + 她的粉）**；结构上给暗色**留位**，这次不做暗色 |
| 状态变色 | **完全不变色** —— 只用动作/表情表达状态，界面永远同一套颜色（最克制那档） |
| 功能开关 | **点击互动 · 气泡提示 · 显示/隐藏 · 不透明度 · 审批由桌宠同意**（审批这项必须配「改完要重启 DSH」的提示） |
| 大小 | 设置里**拉杆 0.6–1.6 倍**（不做拖边角缩放） |

| 设置放哪 | **加托盘** + **右键面板里只加一个「⚙ 设置」按钮**，点它弹出**独立设置弹窗**（设置项不铺进面板） |
| 省电模式 | ❌ 不做（用户未选） |

## 1. 从 Cyrene-Agent 学什么（已核实部分）

我读到的**一手材料**：`src/renderer/ui/tokens.css`、`ui/themes/pearl-white.css`（前 42 KB 里的开头部分）、
`ui/themes/charcoal-pink.css`、README 的界面章节、`renderer/` 文件树、两张官方截图（亮色/暗色）。

### 1.1 值得抄的 7 条

| # | 做法 | 证据 | 我们的做法 |
|---|---|---|---|
| 1 | **颜色全部 token 化**，主题 = 一个覆盖文件 | `tokens.css` 定义 `--rb-bg-0..3`、`--rb-pink-50..700`、`--rb-text-strong/default/muted/faint`、`--rb-success/danger/warning`，连滑块/开关/滚动条/代码块/diff 都有变量 | 我们也定义一套 `--xl-*`，面板/设置窗/气泡共用；以后加"按状态换色"只改 token |
| 2 | **白色不铺满**：页面级底色 ≠ 工作区 ≠ 浮起 | 珍珠白：`surface-page #ECECEE`、`workspace #FFFFFF`、`elevated #FFFFFF` | 面板用「白卡 + 极淡底色 + 阴影」分层，不要一块大白板 |
| 3 | **阴影带颜色**（不是灰黑） | `--rb-shadow-bubble-accent: 2px 2px 4px rgba(255,91,138,.12), 3px 7px 16px rgba(255,91,138,.16)` | 阴影用**她的粉**（低透明度），这是"贵气感"的主要来源 |
| 4 | **边框几乎看不见** | `--rb-border-subtle: rgba(0,0,0,.06)`、`--rb-border-default: #f2f2f2` | 能用阴影就不用边框；必须用就 6% 黑 |
| 5 | **强调色只用在"该注意的地方"** | accent `#ff5b8a` 只出现在主按钮/开关开启/focus 环/链接；大面积都是白或灰 | 粉只给：主按钮、开关开、选中态、focus 环、气泡尖角 |
| 6 | **背景暗纹**（星星 + 弧线）贯穿始终 | 两张截图里都有，低对比、不抢内容 | 用 CSS 径向渐变画星星 + 一条大弧线（呼应秋千绳/羽毛），成本极低 |
| 7 | **设置 = 托盘进入 + 独立设置窗**，面板只放高频 | README：「点击系统托盘图标 → 打开设置」；设置窗左侧分组导航（常规/外观/偏好/模型/用量…） | 托盘 → 设置窗；右键她 → 只留高频（派活/打断/状态） |

### 1.3 明确不抄

## 2. 我们的设计系统（草案，待你确认）

### 2.1 色板（亮色 · 珍珠白）

| 角色 | 值 | 用在哪 |
|---|---|---|
| 页面底 | `#F4EFF2`（极淡的粉灰） | 桌面上的"窗口底色"（如果设置窗需要） |
| 卡片/面板 | `#FFFDFE` | 右键面板、设置窗背景 |
| 悬浮/选中 | `#FFF1F6` | hover 行、列表选中 |
| 主强调（珍珠粉） | `#E889A6`，hover `#F09CB6`，浅底 `#FDE4EC` | 主按钮、开关开、选中、focus 环 |
| 次强调（她的淡紫） | `#A98BD8` | 次按钮、图标、进度条 |
| 点缀（星光金） | `#D9B45E` | 星星、徽章、极少量 |
| 正文 | `#2E2A33` | 主文字 |
| 次文字 | `#6E6779` | 说明 |
| 弱文字 | `#9A93A6` | 状态小字、占位符 |
| 描边 | `rgba(46,42,51,.06)` / `.10` | 极淡边框、分隔线 |
| 阴影 | 粉调 + 紫调各一档（低透明度） | 卡片浮起、按钮 hover |
| 状态色 | 运行 `#5BA98B` · 等待/审批 `#D98A4A` · 完成 `#C9A227` · 出错 `#C7566A` | 状态点/标签（**待你定要不要随状态变色**） |

> 与 Cyrene-Agent 的差异：它的 accent 是更艳的 `#ff5b8a`；我们降饱和到 `#E889A6`，
> 因为我们的场景是"贴在桌面上的一小块"，太艳会抢注意力。这个值你可以直接改。

### 2.2 字号 / 圆角 / 间距 / 动效

- 字号三档：**标题 14px 加粗** / **正文 13px** / **状态 11px**（现在是 12/13.5 两档、全靠颜色分层）
- 圆角：卡片 16px、行/按钮 10px、胶囊 `999px`
- 间距：4 的倍数（4/8/12/16），面板内边距 12
- 动效：打开 110ms `ease-out` 缩放+淡入（现有）；hover 90ms；**不做**花哨动画
- 字体：微软雅黑（现有），不引入外部字体（CSP 限制）

### 2.3 背景暗纹

- 星星：2~3 层 `radial-gradient` 小圆点，透明度 6%~12%
- 弧线：一条大半径 `border` 或 `conic-gradient` 弧，透明度 5%
- 只放在"窗口背景层"，**不进内容区**，避免干扰文字

### 2.4 状态色（✅ 已确认：**A 不变色**）

- **确认方案 A：完全不变色。** 界面永远一套颜色，状态只靠**动作/表情**表达。
- 但颜色仍走 token 结构 —— 以后想改成"随状态变"只需改 token，不改组件（这就是 §1.1 第 1 条的意义）。

## 3. 界面结构（三块 + 气泡）

### 3.1 托盘菜单（新增）

- 内容：`显示 / 隐藏`（Ctrl+Shift+H）· `设置…` · `回到她身边`（把窗口移回主屏可见区）· `检查更新` · `退出`（Ctrl+Shift+Q）
- 意义：**解决"隐藏后叫不回来"**（现在没有托盘，所以不敢做隐藏），也是设置入口
- 技术：Electron `Tray` + `Menu`（原生菜单，Windows 上是系统样式，不需要自绘）
- ⚠️ **2026-10-12 实机结论：本机托盘不可用** —— 对照实验里连 Electron 自带图标都无法登记
  （系统设置里也没有条目），判定为 **Electron 44.5.1 在本机的托盘注册问题**，应用层改不了。
  因此：**托盘代码保留但降级为"尽力而为"**，本机等价入口 = `Ctrl+Shift+H` / 面板 ⚙ / `Ctrl+Shift+Q`。

### 3.2 右键快捷面板（改版，**固定 300×320** —— 用户 2026-10-12 选 B）

- 只放高频：**派活目标 / 输入 / 派活 / 打断 / 状态（tokens·缓存·连接）** + **一个「⚙ 设置」入口按钮**
- ⚠️ **设置项不铺进面板**（用户确认）：面板里只有一个设置按钮，点它弹**独立设置弹窗**（见 §3.3）
- ⚠️ **派活目标必须保持"可收起"**（用户强调）：默认只显示**当前目标那一行**，
  点它才展开会话列表，选完自动收起 —— 换皮**不能**变成常驻列表
- ⚠️ **面板头部只留"头像 + 昔涟"**（用户：去掉「在忙 · 正在处理你的任务」副标题）
- ✅ **窗口尺寸方案：B（固定尺寸，不随内容变高）**
  - **靠输入框吸收高度差**：输入框 `flex: 1`、`min-height` 小 → 折叠时它变大（实测 175px），
    展开时变小（实测 86px），**既不留空白、也不用改窗口尺寸**
  - 为在 320px 里同时装下展开态，做了三处压缩：去掉「派活」小标题与其分隔线、
    去掉"最近 N 个 · 共 M 个"汇总行、列表行高压到 25px
  - **实测（`.cache/ui-mockups/render3.cjs`，Chromium 真实渲染）**：
    `collapsed 内容底 311px / 溢出 −9px`、`expanded 内容底 311px / 溢出 −9px` → **两态都不溢出**
- ⚠️ **头像用项目图标**（用户指定）：`packages/pet-plugin/icon.webp`（270×310），
  面板与设置窗都改用它（圆角方形 + `object-fit: cover` 居中裁）。
  ✅ **`NOTICE.md` 已同步扩用途**：标识图标 **+ 本插件界面里的头像**，三条硬约束不变
- ✅ **会话上限 5 → 3**（`main.js` 的 `MENU_SESSION_LIMIT = 3`，2026-10-12 已改源码）
- 视觉：珍珠白卡 + 粉强调 + 星星暗纹；字号三档；`#notice` 已删（上一轮）
- 尺寸：**先保持 300×320 不变**（避免同时改布局与定位），只换皮 + 收状态 + 加一个按钮
- 交互不变：右键唤出、失焦即关（输入框非空除外）、Enter 发送 / Shift+Enter 换行 / Esc 关闭

### 3.3 设置弹窗（新增，独立小窗）

- **入口两个**：右键面板里的「⚙ 设置」按钮 + 托盘的「设置…」
- 尺寸：约 360×480，**一页三组**（不做左侧导航，设置项还不够多）
- 分组（按已确认需求）：
  - **外观**：大小（0.6–1.6 拉杆）· **不透明度（30–100%）** · 左右翻转（开关）· 自动朝向（开关，开启时按光标方向自动翻）
  - **行为**：点击互动（开关）· 气泡提示（开关）· 审批由桌宠同意（开关 + **「改完需重启 DSH 才生效」提示**）
  - **关于**：版本 · 检查更新 · 恢复默认
- 即时生效（改完立刻看到效果），写盘防抖
- 技术：第 4 个 `BrowserWindow`（跟菜单窗同一套做法：同一 preload 风格、`menu:ready` 式补发、失焦不关）

### 3.4 气泡（顺带统一）

- 现在是 `rgba(255,255,255,.96)` + 深色字 —— 已经很接近珍珠白，**只需**：
  换成同一套 token、圆角 14、粉色尖角/阴影，与其他界面一体化。

## 4. 功能规划（大小 / 镜像 / 开关）

```json
{
  "version": 1,
  "appearance": { "scale": 1.0, "opacity": 1.0, "mirror": false, "autoFace": true },
  "behavior": { "clickInteraction": true, "bubble": true, "approvalViaPet": true }

```

> ✅ **阶段 1 已按此实现（2026-10-12）**：`packages/pet-shell/settings.js`（纯函数，不碰 fs）+
> 自测 `[14] 设置` 共 11 条断言 + **4 条变异测试全部被抓到**；发行包必需清单也加了该文件；
> 自测项数 202 → **213**。**行为不变**（阶段 2 才接进 `main.js`）。
> ⚠️ 刻意**没有** `powerSave`（用户未选）和 `theme`（这次只做亮色）。

- 位置：`packages/pet-shell/.state/settings.json`（和 window.json / model-fit.json 同目录）
- 读：不存在/损坏 → 用默认值（**不报错**）
- 校验：纯函数 `normalizeSettings(raw)`：每项按范围夹紧、类型不对回退默认（照抄竞品做法）
- 写：变更后防抖 300ms；写失败只记日志，不影响运行

### 4.2 每个功能的耦合点（**这是本次最大的技术风险**）

| 功能 | 表面 | 必须一起处理的 |
|---|---|---|
| **大小** | 窗口 `WIDTH/HEIGHT × scale` | ① 构图缓存 `model-fit.json` 要按 scale 失效重测；② 命中掩码坐标系（`mapCssW/H`）；③ 菜单/设置窗定位（按身体居中）；④ 窗口位置 clamp 进工作区 |
| **镜像** | 渲染端 `scaleX(-1)` | **命中测试必须一起翻**：`hit-math.js` 的 `rawToLocal()` 加镜像分支，否则点左边响应右边（这正是本项目栽过的坐标 bug 同类）；菜单方向是否跟着翻（建议不翻） |
| **不透明度** | `win.setOpacity()` | 影响截图为空的问题（自检截图会变淡）——只在调试截图时忽略 |
| **点击互动开关** | 渲染端忽略分区命中 | 关了之后要保证"拖拽仍可用"（不能变成完全点不到） |
| **气泡开关** | 不显示 `activity` 帧 | 通知条已删，这条只影响气泡 |
| **审批走桌宠** | 插件 config | ⚠️ 这是**插件侧**的（要重启 DSH 才生效），做成 UI 开关就得走 profile 写文件 + 提示"需重启 DSH"——**建议这次不做进 UI**，只保留文档说明 |
| **省电模式** | 渲染端降帧 | 需要新增"无交互计时 + 降帧"，影响动画观感；**建议放最后或砍掉** |

## 6. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| **镜像 × 命中测试** | 点左边响应右边 | 抽纯函数 + 行为断言 + 变异测试（本项目硬要求） |
| **大小 × 构图缓存** | 改大小后她变形/偏位 | 按 scale 重建 `model-fit.json`；改完先量再显示（复用现有"构图就绪才显示"） |
| **透明窗圆角 + 阴影** | 白卡在透明窗上边缘会有锯齿/黑边 | 用 `transparent: true` + CSS 阴影，必要时用 `setShape`？——现阶段先接受，实机看效果 |
| **第 4 个窗口** | 窗口多了容易"关不干净"、抢焦点 | 统一走 `ensureXxxWindow()` 模式；一律 `showInactive()`；失焦规则统一 |
| **托盘图标版权** | 用了不干净的图 | **自绘**羽毛/星星符号，不用 `icon.webp` |
| **CSP 限制** | 不能内联样式/外链字体图标 | 图标用内联 SVG；字体用系统字体 |
| **设置写了没生效** | 用户困惑 | 每个开关改完**立即应用**，并在设置窗底部显示"已生效" |

## 7. ✅ 需求已确认（2026-10-12），剩余 3 个小细节

**已确认**：见 §0.1（亮色、不变色、5 个开关、大小拉杆、镜像两种、托盘 + 面板设置按钮 + 设置弹窗、不做省电模式）。

**我已按确认结果替你定的默认值**（觉得不对就说，都不用重新讨论）：

- 不透明度范围 **30%–100%**，默认 100%
- 大小默认 **1.0**（窗口基准 260×300 → 0.6≈156×180，1.6≈416×480）
- 「自动朝向」= **朝鼠标的水平方向**翻，带 **300ms 防抖 + 中间死区**（避免鼠标在她身上扫时疯狂翻）
- 显示/隐藏快捷键 **`Ctrl+Shift+H`**（与现有退出的 `Ctrl+Shift+Q` 配对）
- 审批开关的提示：开关下方**常驻一行小字**「改完需要重启 DSH 才生效」，切换时再弹一次确认
- 托盘图标：**自绘**一个「羽毛 + 星」的简单符号（不用来源不明的现有图标）

**只剩 3 个要你确认**：

2. 审批开关的提示：只要「常驻一行小字」够吗？还是切换时要**弹窗再确认一次**？
3. 「自动朝向」按**鼠标方向**翻，可以吗？（另一种是"按她自己的移动方向"，但我们基本不移动她，所以默认选了鼠标）
