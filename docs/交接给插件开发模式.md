## 2. 现状：为什么它不在插件列表里

**这是本次任务要解决的问题。**

DSH 的插件列表照 **profile 的 bundle 注册表**渲染：

```
~/.dsh/profiles/<name>/package.json
  → dsh.profile.bundles: ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", ...]
```

**实测本机（真实文件）**：

```json
{
  "name": "dsh-profile-desktop",
  "private": true,
  "dependencies": {},
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "@deepseek-ai/dsh-experimental-agent-team-profile"
      ]
    }
  }
}
```

**我们的插件不在这个数组里** → 所以列表里看不到它 ✓（这就是根因）

而它是**手写 patch 行**挂上去的（`~/.dsh/profiles/desktop/cordis.patch.yml`）：

```yaml
- insert:
    - id: xilian-pet
      name: 'C:\...\packages\pet-plugin\index.js'   # 绝对路径直挂
      config:
        pathPrefix: '/xilian-pet'
        captureRawShapes: 20
        minHoldMs: 500
```

**Loader 认它、插件正常工作** ✓，但它**绕过了 bundle 注册流程** ✗ → 不在注册表里 → 列表不显示。

> 当初选手写是必然的：一键安装脚本要能在**没有任何 DSH 工具**的环境里跑通
> （`plugin_manager` 是 DSH 的工具体系，脚本里拿不到）。这是有意识的技术债，现在要还。

## 6. 硬约定：插件与外壳的协议（改插件时不能破坏）

外壳**不是**本任务的对象，但插件是它唯一的数据来源，以下契约必须保持不变：

| 契约 | 值 | 备注 |
|---|---|---|
| 路由前缀 | `/xilian-pet`（来自 config `pathPrefix`） | 外壳写死同名 |
| 健康检查 | `GET /xilian-pet/health` → `{ ok, pid, state, subscribers, code, protocol }` | 外壳启动时探测 |
| 事件流 | `GET /xilian-pet/events`，SSE，`data:` 帧 + `: ping` 心跳 | 外壳靠心跳做静默看门狗（45s） |
| 帧类型 | `state` / `stream` / `snapshot` / `hello` / `notice` / `control` | 见 `packages/pet-plugin/index.js` |
| 我们的协议版本 | `PROTOCOL_VERSION = 1`（**与 DSH 的 `hostProtocolVersion` 无关**） | 在 `/health` 与 `hello` 帧里 |
| 反向操控 | `POST /xilian-pet/control`（`prompt` / `interrupt` / `focus`） | 面板派活/打断用 |
| 代码版本号 | `index.js` 里的 `CODE_REVISION`（当前 25） | 外壳日志会打出来，用于确认"重启到新代码没有" |

**改动插件时请遵守"加法优先"**：新增字段可以，改语义/删字段会让已分发的旧外壳断裂。

### 配置项（`cordis.patch.yml` 与 `setup.mjs` 里写的那一份要对齐）


## 8. 本项目踩过的坑（**照做，别重犯**）

这些都是实测踩出来的，且**都有自测守着** —— 改代码时让它们保持绿就等于不重犯：

| 坑 | 后果 | 现在的守则 |
|---|---|---|
| `.cmd` 里写中文注释 | cmd 用 GBK 解析 UTF-8 字节，注释变成一堆乱码"命令" ✗ | **`.cmd` 必须纯 ASCII，注释也算**（有断言 ✓） |
| `rem` 注释里出现 `>` | cmd 先做重定向 → 凭空造出一个文件 ✗ | `rem` 行不许含 `>`（有断言 ✓） |
| 同一补丁文件名反复用 | 对方很容易拿到旧版 ✗（实际发生过） | 发补丁**带时间戳** |
| 拿"现象"当"原因"下结论 | 我在 `--disable-gpu`、GPU 软件渲染上连错两次 ✗ | **先算数/看计数器，再下结论**；环境事实必须进日志 |
| 断言只检查变量名存在 | 删掉守卫语句测试照样绿 ✗ | 断言**守卫语句本身**；每条新逻辑配**变异测试** |
| 同一份 path 描述两个坐标系 | 窗口被系统撑大后掩码被拉伸，"远离角色反而能拖" ✗ | 命中映射基准 = **画布的 CSS 尺寸**（不是窗口、不是 `innerWidth`） |

**自测与变异测试是本项目的硬要求**：

```bash
node tools/check-plugin.mjs            # 155 项，必须全绿
```

### 12.3 本次额外发现（会咬后来的人，务必记）

1. **profile 里 `- id: <row>` 的覆盖是「整块替换 config」，不是深合并。**

### 12.4 图标契约（2026-10-06 从 `app.asar` 读出的**官方真实逻辑**）

宿主在 `dsh-app-boot/lib/index.js` 内的 `package-meta.js` 里读图标（**不评估插件代码**）：

```js
  ['.svg','image/svg+xml'], ['.png','image/png'],
  ['.jpg','image/jpeg'], ['.jpeg','image/jpeg'], ['.webp','image/webp'],

```

它**抛错的每一种情况**（抛错 ⇒ 卡片图标静默退回默认图案，非常难发现），自测已逐条复刻：

| 官方校验 | 本包当前值 |
|---|---|
| 非空字符串 | `./icon.webp` ✓ |

| 必须是普通文件 | ✓ |
| `stat.size` 与读出的 `bytes.length` 都 ≤ 256 KiB | 11 632 B ✓ |
| **图标不需要 `exports` 条目**（直接按清单目录读文件） | — |
| **`locale` 相反：必须经 `exports` 解析**（宿主走 ModuleLoader） | `./locale/*.json` ✓ |

**不是一条 HTTP 路由** —— 所以换了图标要**让宿主重新读一次元数据**（刷新页面／重启 DSH）才看得到。

渲染侧（`dsh-client-ui-plugin-manager/lib/client.js` 的 `PackageArtwork`）：

```jsx
<img className={...packageImage} src={pkg.meta?.icon} width={size} height={size} alt="" />
// .fO69Vq_packageImage { object-fit: contain }
```

卡片 **36×36**、行内 **30×30** 的正方形盒子 + `object-fit: contain`
⇒ **非正方形图既不会被拉伸也不会被裁**，270×310 按比例缩成约 31×36 居中。
所以**不需要**把图标补成正方形，**也不需要**在导入前缩放或重编码（原样入库保真度最高）。

### 12.7 更新检查（2026-10-06）：让用户能自己问"我是不是最新"

公开分发之后，最大的支持负担是"用户不知道自己装的是哪一版、也不知道有没有新版"。

| 产物 | 作用 |
|---|---|
| `versions.json`（仓库根，**受版本控制、不进发行包**） | 发布清单：`latest` / 发布日期 / 更新说明 / 每种形态的 zip（文件名 · 大小 · **sha256** · 下载地址） |
| `tools/lib/update-check.mjs` | 全部逻辑：semver 比较、清单解析、多源回退、**打印行生成**（抓取可注入 → 能离线自测） |
| `tools/check-update.mjs` | 命令行；退出码 `0` 已最新 / `10` 有新版本 / `1` 失败 |
| `检查更新.cmd`（新增，ASCII-only） | 用户双击入口；自动发现 Node（包内 → DSH runtime → PATH） |
| `package-release.mjs` | 打完包**顺手写清单**（sha256 手抄一定会和实际 zip 对不上，而用户正是拿它核对） |
| `setup.mjs` 结尾 | 安装完**顺手查一次**（见下面"两个入口策略相反"） |

**⚠️ 三条设计约束，改之前先读：**

1. **「检查失败」永远不能写成「已是最新」。** 这是更新检查器最经典的谎言 ——
   用户于是错过更新，还以为自己查过了。`status` 明确分 `failed` / `up-to-date` / `available` / `ahead`；
   失败时**绝不出 ✅**（自测里有专门一条断言这个）。
2. **两个入口的失败策略相反**：
   · `检查更新.cmd`（用户主动）→ 失败**如实说**，还列出每个来源各自怎么失败
   · `setup.mjs` 结尾（安装时）→ 失败**一个字都不打**
   因为安装那侧输出会整份写进 `install-log.txt`，而那是用户报 bug 时发给开发者的 ——
   里面冒一句"检查更新失败"会被**误读成安装失败**。安静模式失败时**连退出码都是 0**。
   自测里有两条 `★` 断言专门钉这个（**变异测试验证过**：把静默去掉 → 当场失败）。
3. **来源是有序数组**（`UPDATE_SOURCES`），逐个试、谁通用谁，输出里报告**是哪个源答的**。
   主源用 jsDelivr（`cdn.jsdelivr.net`）而不是 `raw.githubusercontent.com` —— 后者在国内经常不可达。
   **将来开 Gitee 镜像 = 往数组里加一行**，顺序即优先级。

**已知取舍**：jsDelivr 对**分支引用最长缓存 12 小时** —— 刚发新版时用户可能还看到旧的。
所以输出里永远同时给**发布页链接**，用户永远有地方自己确认。

**实测证据**（2026-10-06，本地起 HTTP 服务器当清单源跑的端到端）：
用户主动查 = 完整信息 + 退出码 10；安装时 `--quiet` = **恰好 1 行**；
已是最新时 `--quiet` = **0 字节输出**、退出码 0；检查失败时 `--quiet` = **0 字节输出**、退出码 0、
而用户主动查则如实报"这不等于已是最新"、退出码 1。真实网络下（仓库尚未推送 `versions.json`）
两个来源都返回 **HTTP 404**，被正确报成失败 —— 而且这说明 **jsDelivr 与 raw 在国内容器里都可达**。

## 12.8 官方安装可以**完全命令行**完成（2026-10-06 更正）

**结论：`dsh plugin --profile <profile> add <本地目录>` 能独立完成官方安装**，不需要点图形界面。
于是 `安装.cmd` 的**默认**路径换成了它（手写 patch 降级为 `--patch` 退路）。

### 为什么以前认为不行

以前只验过 `--dump-config`，而它对 `desktop` profile 直接拒：

```
$ dsh --profile desktop --dump-config
error: profile "desktop" is managed exclusively by the Electron application
```

**但这个限制只管「boot / 看配置树」**，不管 `plugin` 子命令 —— 子命令走的是
`dsh/lib/plugin-*.js` 的 `runPlugin()`，实测对 `desktop` 完全可用。

### 实测（本机 desktop profile，remove → add 一轮）

```powershell
$dsh = 'F:\dsh\resources\runtime\cli\bin\dsh.cmd'
& $dsh plugin --profile desktop remove '@local/xilian-pet-plugin'
#  → dependencies 里的 link: 没了 **且** dsh.profile.bundles 里那一项也没了
& $dsh plugin --profile desktop add 'C:\...\xilian pet\packages\pet-plugin'
#  → + @local/xilian-pet-plugin link:C:/…/packages/pet-plugin
#  → dsh.profile.bundles 里重新出现 @local/xilian-pet-plugin ✓
# 退出码 0；package.json 用 Node 按 UTF-8 回读，中文路径**没有被写坏**
```

改完后 `/health` 仍 `ok:true, code:26`（运行中的实例不受影响）；
`uptimeMs` 在安装那一刻**归零** —— 说明 **profile 变化会让 DSH 自己重载插件**
（也就是官方安装可能**不需要重启 DSH**；但安装器仍提示重启，保险）。

### 实现要点（改之前先读）

1. **不要直接 spawn `dsh.cmd`**：Windows 上 Node **不能直接 spawn `.cmd`**
   （Node ≥18.20/20.12 的安全修起抛 `EINVAL`），绕 `cmd.exe` 又要趟引号沼泽（路径含空格与中文）。
   `dsh.cmd` 本体只有三行，做的就是：
   `ELECTRON_RUN_AS_NODE=1 "<install>\DeepSeek Harness.exe" --expose-internals "<…>\dsh-desktop-host\lib\cli.js" %*`
   —— 我们照做，参数交给 Node 正常转义。
2. **`cli.js` 在 `app.asar` 内部，`existsSync` 恒为 false**（对普通 Node，asar 只是个**文件**）。
   所以可用性判断**只看那个 exe 存不存在**；asar 内部的路径交给 Electron 自己解析。
   （实测踩过：写成 `existsSync(cliExe) && existsSync(cliJs)` → `cliReady` 永远为假，默认路径白白退回手写 patch。）
3. **装完必须回读 `package.json` 校验**（`link:` 依赖 + `bundles` 两项都在），不能只信退出码。
4. **走官方前先摘掉手写行**，否则插件被加载两次（两个实例、两套 SSE）。
5. 安装目录来自注册表 `InstallLocation`（`find-node.cmd` 里，**无条件**解析 ——
   以前它只在"找不到 Node"时才跑，于是"Node 已就绪 + 要装插件"这条最常见的路上反而拿不到）。
   找不到 CLI 时自动退回手写 patch；`--patch` / `--official` 可强制指定。

## 12.9 审批默认由**关**改成**开**（opt-in → opt-out，2026-10-06）

**现象**：朋友测试「审批走桌宠」，审批**没有**走桌宠 —— 直接弹了 DSH 原来的界面提示，
而桌宠、安装日志、`/health` 一切正常，从任何界面都看不出异常。

**根因**：`approval.viaPet` 原来是 **opt-in** ——

```js
const approvalViaPet = approvalConfig.viaPet === true   // 旧：不写就是关
```

而配置有**两个来源**，其中一路根本没写这个键：

| 安装方式 | 生效的 config 来自 | `approval` 键 | 结果 |
|---|---|---|---|
| 手写 patch（`setup.mjs`） | 它写进 profile 的那一行 config | **没有** | 审批静默走 GUI ✗ |
| 官方 bundle / 图形界面 | `packages/pet-plugin/cordis.patch.yml` | 有，但是 `false` | 同样走 GUI ✗ |
| 本机（早期手改过） | profile 里的覆盖行 | 有，`true` | 正常 ✓（所以本地怎么测都没事） |

**改法**（两处都改，缺一不可）：

1. `index.js`：`approvalConfig.viaPet !== false` —— **不写 = 开**，显式 `false` 才关。
   这样「config 里没有 `approval` 键」的那些安装路径也自动正确。
2. `cordis.patch.yml`：`viaPet: true`（官方 / 图形界面安装拿的是这份）。

**为什么改默认值是安全的**（这条是前提，别漏）：桌宠没连上时 handler **立刻交棒**：

```js
// ① 功能没开 / 桌宠没连上 → 立刻交棒：行为与启用前完全一致，绝不把审批卡死
if (!approvalViaPet || connections.size === 0) return next()
```

所以唯一的行为变化发生在**桌宠连着的时候** —— 那正是用户要的。代价：桌宠连着但没人点，
要等 `timeoutMs`（默认 60 秒）才交棒给 GUI。不想要就写 `viaPet: false`。

**顺带**：`CODE_REVISION` 26 → 27。远程确认「新代码真的生效」就看 `/health` 的 `code`，
而 `config.approvalViaPet` 能直接读出**生效后**的开关值（这也正是当初把它加进回声的理由）。

**自测变化**：把钉住「默认关闭」的那条改成「默认交给桌宠」，另加一条「显式 `false` 就一个
应答者都不注册」；两个**探针**测试原先依赖「不写 viaPet = 不注册」，现在显式传
`viaPet: false` 隔离噪声（否则应答者会变成 2 个）。200 项全绿。
