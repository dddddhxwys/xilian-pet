## 二、逐项详述

### S1（高）agent shell 的 TLS 栈坏了：Schannel `SEC_E_NO_CREDENTIALS`

**现象**：从 agent shell 发起的 HTTPS 请求全部失败，但**仅限 Schannel 系**。

| 客户端 | 结果 | 原文报错 |
|---|---|---|
| `curl.exe` 8.21 (Schannel) | FAIL | `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)`；`-k` 也失败 |
| PowerShell `Invoke-WebRequest` / `.NET` | FAIL | `基础连接已经关闭: 接收时发生错误。`（全部 7 个测试域名） |
| `git`（Windows 版默认 Schannel） | FAIL | `fatal: ... schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` |
| **Node / npm / pnpm（自带 OpenSSL）** | **OK** | `npm ping` → `PONG 1570ms`；`fetch` 200 |
| `git -c http.sslBackend=openssl`（已验证绕过） | **OK** | `git ls-remote https://gitee.com/mirrors/electron.git` 正常返回 refs |

**根因判断**：`CryptSvc`/`KeyIso` 均在运行、`ProgramData\Microsoft\Crypto\RSA\MachineKeys` 可读，**不是系统加密服务故障**。结合工作区 ACL 里出现的 `S-1-4-708504501-198681388`（AppContainer 能力 SID）ACE，可判断 **agent shell 跑在受限令牌/AppContainer 语境下**，Schannel 无法取得凭据。属**该 shell 语境**问题，你自己开的终端大概率正常（请顺手验证一次 `curl -I https://registry.npmjs.org`）。

**影响**：任何"下载/安装靠 PowerShell 或 curl"的脚本在 shell 里会静默失败——这是本次体检里最容易在后期炸掉的一类坑（Electron、模型、素材下载脚本常见）。

**建议**
1. 本仓所有联网动作固定走 node 系：`npm` / `pnpm` / `node fetch`。
2. git 操作加 `-c http.sslBackend=openssl`（或提权改全局 `git config --global http.sslBackend openssl`）。
3. 需要抓网页写进文档时，用 harness 的 `web_fetch`，不要用 `Invoke-WebRequest`。

## 六、补充发现（2026-09-29 晚，搭 Phase 0 骨架时实测）

搭骨架过程中又撞出 4 个报告正文没覆盖的坑。它们不属于"初始环境扫描"，但都属于**环境隐患**，一并记录。

### S14（高）Electron / Chromium 无法在 agent shell 内启动

**现象**（逐级定位）：

| 尝试 | 结果 |
|---|---|
| `electron.exe --version`（默认设置） | 无输出，退出码 `-2147483645` = `0x80000003` STATUS_BREAKPOINT |
| `electron.exe --no-sandbox --disable-gpu --version` | ✅ 打印 `v44.4.5`，exit 0 |
| 完整启动应用（加 `--no-sandbox --disable-gpu`） | ❌ `FATAL:mojo\public\cpp\platform\platform_channel.cc:108] Check failed: . : 拒绝访问。 (0x5)` |

**根因**：Chromium 的 Mojo IPC 在 Windows 上通过**命名管道**通信，而受限沙箱禁止创建命名管道（这正是"confined 模式不能打开命名管道"的那条边界）。`--no-sandbox` 只能绕过 Chromium 自己的沙箱，绕不过 DSH 的外层沙箱。

**影响**：**任何 Chromium/Electron 程序都无法在本 shell 内运行** —— 不只是桌宠。这意味着所有需要"真跑一下看效果"的 Electron 侧工作，我都只能靠提权单次验证，或在你自己终端里做。

**应对**：启动脚本已内置探测（`spawnSync(electron.exe, ['--version'], {stdio:'ignore'})`，用 `ignore` 是为了避开管道 EPERM），失败时自动追加 `--no-sandbox --disable-gpu` 并打印原因。你在自己终端里跑则走默认沙箱。

> 附带印证：`Start-Process` 在本沙箱内被直接拒绝（`Access is denied`），而直接 `& exe` 正常 —— 提权/进程创建的边界比想象中窄。

### S15（中）Electron 二进制安装链路在本机是坏的

- `electron` 的 postinstall 被 pnpm 10+ 默认拦截 → 需要 `onlyBuiltDependencies: [electron]`（本仓已配）。
- 放行后它的 `install.js` 仍失败：zip 缓存目录读的是 **小写** `electron_config_cache`，默认在 `%LOCALAPPDATA%\electron\Cache`（沙箱外，被拒）；改到工作区后**依然空转**（CPU 0、无连接、10 分钟无输出），退出码 1。
- **实测可行的替代**：自己下载 + 纯 JS 解 zip。镜像速度差异极大 —— npmmirror **~85 KB/s**（150.9 MB 要半小时），**华为云 ~4 MB/s 单连接 / 11 MB/s 八路并行，14 秒跑完**。已固化成 `tools/fetch-electron.mjs`、`tools/probe-mirrors.mjs`。

### S16（低）pnpm 在含空格/非 ASCII 路径下的 linker 崩溃

`pnpm install` 报 `[ERR_PNPM_SYMLINK_FAILED] [symlinkAllModules] Maximum call stack size exceeded`。
规避：`nodeLinker: hoisted` + `packageImportMethod: copy`（已写入 `pnpm-workspace.yaml`）。

### S17（低，但踩了两次）工具面本身的边界

| 事项 | 结论 |
|---|---|
| `hidden` 属性 | 被作者样式里的 `display:flex` 覆盖 → 元素"该隐藏却显示"。需 `[hidden]{display:none!important}` 兜底 |
| 元素 id 与 preload 桥撞名 | `<img id="pet">` 自动创建 `window.pet`，与 `exposeInMainWorld('pet', …)` 撞名 → 渲染端 `SyntaxError`，**整页 JS 静默失效**（CSS 仍生效，截图极具迷惑性） |
| pwsh 改写含中文的源码 | `Get-Content -Raw` + `-replace` 再写回会把 UTF-8 注释变成乱码，并可能吞换行导致语法错误。**改源码只用 edit/write 工具** |
| `capturePage()` 自检 | 离屏截图 + `console-message` 诊断是"看不见屏幕"时唯一可靠的验证手段，已内置为 `PET_SNAPSHOT=<png>` |
